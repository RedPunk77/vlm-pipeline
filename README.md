# Grounded VLM

Пет-проект на Qwen2.5-VL для visual grounding: модель находит объекты и текст, возвращает structured JSON с координатами, а независимые YOLO и OCR отдельно проверяют её ответ

Модель может придумать объект или ошибиться с координатами, поэтому её ответ сравнивается с независимыми результатами детектора и OCR, а качество измеряется по разметке

## Что есть сейчас

- Локальный запуск Qwen2.5-VL через Transformers
- Проверка JSON и границ рамок через Pydantic
- Проверка объектов через YOLO11, текста — через EasyOCR
- Контраст и доля границ внутри рамки через OpenCV
- Сохранение сырого ответа, подтверждений и причин фильтрации
- Метрики до и после проверки, картинки с рамками и Markdown отчёты
- Продолжение прогона через `--resume` с проверкой настроек и входных файлов
- Сравнение способов проверки без повторной генерации Qwen
- Подготовка выборки COCO и синтетическое демо без весов
- 22 теста, включая проверку реального процессора при наличии его локального кеша

Реальный запуск проверен на Mac с 16 ГБ памяти через MPS, CUDA и CPU для генерации пока не проверялись

## Что получилось

На промежуточном прогоне из 45 изображений COCO VLM отдельно показала 0,119 Grounding IoU, recall 0,140 и 68,9% валидных JSON. После фильтрации YOLO hallucination rate снизился с 0,136 до 0,065.

После настройки формата ответа на одном изображении провели пилот на двух других фотографиях COCO с четырьмя размеченными объектами

| Метрика | Исходный Qwen | С заменой рамок на YOLO | С сохранением рамок Qwen |
| --- | --- | --- | --- |
| Валидный JSON | 100% | 100% | 100% |
| Recall | 50% | 50% | 50% |
| Grounding IoU | 0,486 | 0,465 | 0,486 |
| Точность полного ответа | 50% | 50% | 50% |

Qwen нашёл человека и поезд, но пропустил второго человека и мяч, среднее время обработки — около 55 секунд на изображение без загрузки модели

Замена рамок ухудшила IoU, поэтому по умолчанию проверка теперь сохраняет координаты Qwen, это устраняет ухудшение на пилоте, но не решает пропуски

## Быстрый старт без GPU

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/run_demo.py --count 10 --seed 42 --out examples/demo_output
python -m unittest discover -s tests -v
```

Демо рисует PNG с красными прямоугольниками, добавляет ошибки в синтетические ответы и проверяет их цветовым детектором, Qwen, YOLO и OCR здесь не запускаются

В `examples/demo_output` появятся изображения, `manifest.jsonl`, `outputs.json` и рассчитанный `metrics_report.json`, эти метрики проверяют код, а не качество Qwen

## Запуск реальных моделей

```bash
python -m pip install -r requirements-models.txt
python -m src.cli infer data/photo.jpg --device mps --out outputs/photo
```

Для NVIDIA: `--device cuda`, для автоматического выбора — `--device auto`, для CPU — `--device cpu`

По умолчанию используются `Qwen/Qwen2.5-VL-3B-Instruct`, `yolo11n.pt` и EasyOCR с английским и русским языками, параметр устройства относится к Qwen, OCR работает на CPU

Первый запуск скачивает веса, только Qwen3B занимает ~7,5 ГБ на диске (довольно тяжелая модель), не упоминая расход RAM

```bash
python -m src.cli infer data/photo.jpg \
  --device mps --max-pixels 200704 --max-new-tokens 768 \
  --box-policy preserve --out outputs/photo-small
```


Кеш Qwen хранится в `.cache/huggingface`, настройки YOLO — в `.cache/ultralytics`, веса OCR — в `.cache/easyocr`, OCR загружается при первом текстовом предсказании

## Формат ответа и проверка

Координаты `[x1, y1, x2, y2]` выражены в пикселях изображения после EXIF-поворота, модель видит подготовленное изображение, её координаты пересчитываются обратно

```json
{
  "objects": [
    {"label": "cat", "kind": "object", "bbox": [50, 40, 200, 180], "text": null},
    {"label": "text", "kind": "text", "bbox": [10, 10, 90, 30], "text": "OPEN"}
  ]
}
```

Это пример структуры, не результат генерации, для обычных объектов используем английские названия классов COCO, для текста — `label=text` и точную транскрипцию

1. Qwen получает изображение и явный пример формата, версия промпта сохраняется в отчёте
2. Ответ проверяется по схеме, неверные рамки и сломанный JSON не исправляются молча
3. Объекты сопоставляются с YOLO по классу и IoU, текст — с OCR по строке и IoU
4. Пары выбираются жадно от большего IoU к меньшему, одно подтверждение нельзя использовать дважды
5. Подтверждённые объекты остаются в ответе, остальные сохраняются в `audit` как `unconfirmed`

По умолчанию порог совпадения — IoU ≥ 0,3, уверенность проверяющего модуля ≥ 0,4, YOLO сначала отбирает детекции с confidence ≥ 0,25

Режим `--box-policy preserve` сохраняет рамки Qwen, `--box-policy detector` заменяет их рамками подтверждения, в аудите есть обе рамки и признак изменения

`unconfirmed` означает отсутствие подтверждения, а не доказанное отсутствие объекта, у YOLO ограниченный набор классов и собственные ошибки, поэтому фильтрация может снизить recall

CV считает контраст и границы, но эти признаки сами по себе не доказывают класс объекта и не используются как основание для подтверждения

В полном отчёте есть `raw`, `baseline`, `verified`, `parse_error`, `audit` и `evidence`, при ошибке схемы обе сцены равны `null`, свободное описание сцены пока не генерируется

## Оценка на своём наборе

Manifest — JSONL, одна строка на изображение, пути считаются относительно manifest

```json
{"image":"images/001.jpg","objects":[{"label":"cat","kind":"object","bbox":[50,40,200,180],"text":null}]}
{"image":"images/002.jpg","objects":[{"label":"text","kind":"text","bbox":[10,10,90,30],"text":"OPEN"}]}
```

Разметка должна включать все оцениваемые объекты и текст, иначе правильные предсказания будут считаться лишними, автоматического перевода названий классов и словаря синонимов пока нет

Для COCO скрипт скачивает архив аннотаций один раз и только выбранные фотографии

```bash
python scripts/prepare_coco.py --count 20 --seed 42 --out data/coco-eval
python -m src.cli evaluate data/coco-eval/manifest.jsonl \
  --object-labels data/coco-eval/labels.json \
  --device mps --max-pixels 200704 --out outputs/coco-eval
```

## Метрики

В оценке используетсясопоставление по IoU при одинаковом классе и типе, для текста дополнительно сравнивается строка без учёта регистра и повторных пробелов

Порог успешной локализации: IoU ≥ 0,5, он отличается от порога внутри проверяющего пайплайна

| Метрика | Расчёт |
| --- | --- |
| `hallucination_rate` | Доля предсказаний без успешной пары в разметке |
| `grounding_iou` | Сумма IoU сопоставленных пар / число областей в разметке, пропуски дают 0 |
| `structured_accuracy` | Доля изображений с валидной схемой, всеми найденными областями и без лишних предсказаний |
| `schema_valid_rate` | Доля изображений с корректной схемой и координатами |
| `recall` | Число успешных пар / число областей в разметке |

Здесь hallucination rate включает неверную локализацию и дубли, а не только выдуманный класс, напрямую сравнивать эту метрику с чужими статьями без сверки определений нельзя

Если предсказаний нет, hallucination rate равен `null`, при пустой разметке recall и grounding IoU равны `null`, пустой валидный ответ считается точным только для пустой разметки
